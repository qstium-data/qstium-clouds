# Карта облаков для модуля «Земля»

Раз в час собирает глобальную карту непрозрачности облаков из **готовых профессиональных масок облачности**
геостационарных спутников и кладёт её в Cloudflare KV, откуда её раздаёт воркер
`qstium-earth-clouds` (`tools/earth/clouds-worker/worker.js`, маршруты `/m/…`).

Почему так: нынешняя формула в браузере (`earth-clouds.js`) по одному ИК-кадру находит ~69 % облаков
при ~21,5 % ложных. Мозаика готовых масок на том же стенде (8 случаев 06.11.2026, эталоны GOES ACM /
Himawari CMSK / VIIRS JRR, эталон случая из голосования исключён) — **88,4 % найдено / 9,0 % ложных**.

| | найдено / ложных, % |
|---|---|
| нынешняя ИК-формула | 69,1 / 21,5 |
| этот конвейер, все маски (без эталона случая) | 88,8 / 10,1 |
| + ночной фильтр для Средней Азии (включён) | **88,4 / 9,0** |
| — день / ночь | 91,4 / 5,8 · 85,5 / 12,1 |
| — Казахстан день / ночь | 89,6 / 8,2 · 81,8 / 13,6 |
| если упал IODC | 87,7 / 9,6 |
| только GCC (упали все спутниковые маски) | 87,0 / 12,1 |
| без GCC (стенд занижает: эталон случая исключён, ячейки уходят в ИК-формулу) | 78,8 / 14,6 |

Стенд — один день (06.11.2026), за пределами ±56° широты не проверялся.

**Ночной фильтр — оговорка.** Его параметры подобраны на чётных 64-столбцовых блоках тех же 8 случаев, и
цифра «Казахстан ночью 84,5 / 22,6 → 81,8 / 13,6» наполовину посчитана на данных подбора. На отложенных
(нечётных) блоках Казахстана ночью: **80,1 / 22,5 → 74,6 / 10,8**, то есть −5,5 п. п. найденного за
−11,7 п. п. ложных (сумма ошибок 42,4 → 36,2 — фильтр всё ещё в плюсе). Это одна ночь одного региона:
до проверки на 2–3 других ночах с эталоном VIIRS фильтр считать полезным предварительно; выключается `--skip night`.

## Как считается (файлы)

- `sources.py` — загрузка источников и перевод в доли облачности на сетке. Большие HDF5 (Himawari 380 МБ,
  GCC 1,3 ГБ, GOES 25 МБ) не качаются целиком: читаются оглавление и сжатые куски нужной переменной
  параллельными HTTP Range-запросами (за час уходит ~60 МБ). Range проверяется строго (206, тот же
  Content-Range, длина тела): сервер, отдавший весь файл вместо куска, обрывается сразу.
  GMGSI LW ≥ 240 (≤ 178 K: край диска IODC у Антарктиды, 23–93° в. д. южнее 55° ю. ш.) — нет данных;
  файл, где годных точек меньше половины, — источник «нет».
- `mosaic.py` — сведение: взвешенное голосование масок (вес спутника = clip((72° − угол обзора)/15°),
  IODC гаснет за 6° до краёв слоя, GCC с весом 0,5). Где суммарный вес масок < 0,1 (самый край дисков,
  когда нет GCC), альфа плавно переходит в прежнюю ИК-формулу сайта.
  Покрытие cov = clip((доля − 0,5)/0,3); плотность s = насколько ячейка холоднее ясного фона по ИК
  или ярче его в видимом днём; альфа = cov · (0,45 + 0,55 · s^0,6); к полюсам (65…70°) гаснет до нуля —
  дальше 70° GCC нет, а спутники не голосуют. Фон широты — 70-й перцентиль ясных ячеек строки
  (только строки с ≥ 20 ясными), медиана и гаусс по строкам.
- `nightfilter.py` — ночью в Средней Азии (25…100° в. д., 28…66° с. ш.) снимает облака, которые
  многоканальная проверка (GMGSI LW/SW/VIS + прогноз GFS: температура поверхности, осаждённая вода,
  суша) считает ясным небом (C ≤ 0,05). Маска IODC ночью над сушей видит лишние облака.
- `build_mask.py` — запуск: какие часы делать, параллельная загрузка, сведение, WebP, манифест, KV.
- `cfkv.py` — запись/чтение Workers KV через REST API (без wrangler), повторы с паузой 2–20 с.

Каждый источник необязателен: упал, опоздал (общий срок 300 с) или нет файла — голосуют остальные;
нет ни одной маски — ИК-формула; нет только видимого канала — плотность по ИК. Без кадра GMGSI LW час
не собирается (появляется к ЧЧ:39). Что вошло и что нет — в манифесте (`сведения[час].маски`, `.нет`).

Защита от сбоев:
- манифест пишется после **каждого** собранного часа — обрыв запуска не теряет собранное;
- ошибка одного часа (KV, сведение) не роняет остальные; код выхода 1 — только если не собран ни один;
- новый час не начинается после `--budget-min` (17 мин; один час — до ~5,5 мин, срок задачи 25 мин);
- кадр, где облачно (альфа > 0,2) меньше 15 % сетки, не пишется (на Земле облачно ~60–70 %; так выглядит
  битый вход), прежний остаётся;
- кадр не заменяется более бедным: ни при пересборке по опоздавшему источнику, ни по `--hour`
  (затереть всё равно — `--force`); источник, который при пересборке так и не скачался, второй раз не ждём
  (`сведения[час].пересборка`);
- план берёт самые новые из **всех** недостающих часов за 26 ч — после простоя Actions старые дыры тоже заполнятся.

## Источники, лицензии и подписи

| источник | что берём | откуда | условия |
|---|---|---|---|
| GOES-18, GOES-19 ABI L2 Clear Sky Mask (ACMF) | маска, полный диск ЧЧ:00 | `s3://noaa-goes18`, `s3://noaa-goes19` | NOAA Open Data Dissemination: без ограничений, но изменённые данные нельзя выдавать за исходные и нельзя подразумевать одобрение NOAA |
| Himawari-9 AHI Cloud Mask (AHI-L2-FLDK-Clouds, CMSK) | маска | `s3://noaa-himawari9` | то же (данные JMA, продукт NOAA/NESDIS); одобрение NOAA/JMA не подразумевать |
| Meteosat CLM, IODC (45,5° в. д.) и 0° | маска | WMS `view.eumetsat.int`, слои `msg_iodc:clm`, `msg_fes:clm` | EUMETSAT Data Policy: Core, CC BY 4.0 — подпись по ст. 6.3 и ссылка на лицензию |
| NASA LaRC SatCORPS GCC-GEO v2 | `cloud_phase` | `satcorps.larc.nasa.gov/prod/GCC-GEO` | исследовательский продукт, без гарантий; просят простую благодарность со ссылкой на satcorps.larc.nasa.gov (вежливо — одно письмо W. Smith об использовании, разрешение не нужно) |
| NOAA/NESDIS GMGSI LW / VIS / SW | плотность, запасная формула, ночной фильтр | `s3://noaa-gmgsi-pds` (NetCDF; кадры nowCOAST не годятся — плавает шкала) | NOAA Open Data Dissemination (как выше) |
| NOAA NCEP GFS 0,25° | Tskin, PWAT, суша — окно −15…130° в. д. | NSF Unidata THREDDS NCSS (`thredds.ucar.edu`) | данные NOAA — общественное достояние; **сервис Unidata — только для образования и исследований, без гарантий для оперативной работы**, в User-Agent контакт (есть: `QST_CONTACT`, по умолчанию e-mail с сайта) |

Подписи в манифесте собираются из `SRC` в `build_mask.py` (за час — `сведения[час].подписи`, они же со ссылками
в `сведения[час].ссылки`):

- Derived from NOAA GOES-18 ABI L2 Clear Sky Mask (NOAA Open Data Dissemination)
- Derived from NOAA GOES-19 ABI L2 Clear Sky Mask (NOAA Open Data Dissemination)
- Derived from Himawari-9 (JMA) AHI Cloud Mask by NOAA/NESDIS (NOAA Open Data Dissemination)
- Contains modified EUMETSAT Meteosat data 2026 (CC BY 4.0) — ссылка https://creativecommons.org/licenses/by/4.0/
- Derived from NASA LaRC Satellite ClOud and Radiation Property retrieval System (SatCORPS) GCC-GEO — ссылка https://satcorps.larc.nasa.gov
- Derived from NOAA/NESDIS GMGSI (NOAA Open Data Dissemination)
- NOAA NCEP GFS via NSF Unidata THREDDS (только когда сработал ночной фильтр) — ссылка https://www.unidata.ucar.edu

И общая оговорка `оговорка` в манифесте: карта — производная QSTiUM, не исходные данные и не одобрена
NOAA, JMA, EUMETSAT, NASA. **Ссылки показывать обязательно** (CC BY 4.0 требует ссылку на лицензию,
SatCORPS — на свой сайт).

## Что получает клиент

Через воркер `https://qstium-earth-clouds.iverrum.workers.dev` (после выкладки воркера):

- `GET /m/manifest.json` (кеш 2 мин) —
  `{в, обновлено, формат: "webp", размеры, сетка: {crs: "CRS:84", запад: -180, восток: 180, север: 72.5, юг: -72.5, высота: {"2048": 824, "4096": 1648}}, значение, оговорка, кадры: [ISO…], сведения: {ISO: {маски, нет, главный, без_масок, видимый, ночной_фильтр, облачно, собрано, подписи, ссылки: [{текст, url}], байт: {"2048": …, "4096": …}, пересборка?}}}`.
  `кадры` — часы за последние 26 ч по возрастанию, ISO вида `2026-11-07T04:00:00Z`. Воркер сам выбрасывает
  из списка часы старше 30 ч (кадры к тому времени истекли в KV), даже если конвейер встал.
  **Время сравнивать через `Date.parse`, а не строкой**: старый `/manifest.json` (`/f/`) пишет
  `2026-11-07T04:00:00.000Z`. `размеры` — размеры последнего запуска; какие есть у конкретного часа — ключи `сведения[ISO].байт`.
- `GET /m/2048/<ISO>.webp`, `GET /m/4096/<ISO>.webp` — WebP без потерь, R = G = B, значение
  0…255 = непрозрачность облака 0…1. Сетка равнопромежуточная: строка 0 — 72,5° с. ш., столбец 0 — 180° з. д.,
  центр ячейки i — −180 + (i + 0,5) · 360/W, строки j — 72,5 − (j + 0,5) · 145/H. **У 4096 высота 1648**
  (у старых `/f/4096` — 1650: шаг по широте чуть другой, к низу кадра сдвиг около строки).
  2048 — ~0,85 МБ, 4096 — ~3,1 МБ.
  **Петлю за сутки крутить на 2048** (26 кадров ≈ 22 МБ; на 4096 ≈ 81 МБ мобильного трафика),
  4096 грузить только для текущего кадра вблизи.
  Свежий час (моложе 4 ч) может быть пересобран, когда подтянется опоздавший источник, — поэтому он
  кешируется на 10 мин, старше — на сутки; сверять `сведения[ISO].собрано`.
- Кадра нет — его нет в `кадры` (или 404). Кадры живут в KV 30 ч и исчезают сами. Ни одной маски — не
  ошибка: кадр целиком из ИК-формулы (`главный.ik` = 1).

## Запуск локально

```
pip install -r requirements.txt
python build_mask.py --out-dir out --max-hours 2 --preview     # в папку, KV не трогает
python build_mask.py --hour 2026-11-07T04 --sizes 2048,4096 --report out/run.json
```

В папке ключи те же, что в KV, только без двоеточий в имени файла (Windows): `out/m/2048/2026-11-07T040000Z.webp`.
`--preview` кладёт рядом наглядный PNG (альфа белым поверх ИК/видимого, снизу исходный ИК).
`--skip iodc,night` — отключить источники; `--format png` — PNG вместо WebP (на 7 % крупнее);
`--quality 90` — WebP с потерями (−29 % веса, средняя ошибка ~1/255; по умолчанию без потерь).

## Как выложить

0. **Сначала решить про риск условий GitHub (см. «Расход»).**
1. Владелец создаёт **публичный** репозиторий (минуты Actions в публичном репо бесплатны) и кладёт в корень
   `build_mask.py`, `sources.py`, `mosaic.py`, `nightfilter.py`, `cfkv.py`, `requirements.txt`, `README.md`,
   а `workflow.yml` — как `.github/workflows/clouds.yml`.
2. В Cloudflare: отдельный API-токен только с правом «Account → Workers KV Storage → Edit».
   Id пространства KV `qstium-earth-clouds` — в панели Workers → KV (или его печатает `deploy.py`).
3. Секреты репозитория: `CF_ACCOUNT_ID`, `CF_API_TOKEN`, `CF_KV_NAMESPACE_ID`.
4. Выложить воркер с маршрутами `/m/…`: `python tools/earth/clouds-worker/deploy.py` (старые маршруты не менялись).
5. Первичное заполнение: Actions → clouds → Run workflow с `max_hours` = 8, **три-четыре раза подряд**
   (каждый запуск — до ~17 мин и сам берёт самые новые из недостающих часов; манифест пишется после каждого часа).
   Дальше он идёт сам в ЧЧ:55 (все источники часа ЧЧ к ЧЧ:52 уже есть; GitHub часто запускает позже — не страшно).

## Расход

- Один час: ~60 МБ загрузки, 45–110 с обычно, до ~250 с, когда тормозит WMS EUMETSAT или GCC (общий срок
  источника 300 с); сведение ~1 с (+5 с на 4096).
- Actions: ~2–2,5 мин на запуск с установкой зависимостей из кеша → ~1500–2200 мин в месяц (бесплатно в публичном репо;
  в закрытом это весь бесплатный лимит 2000 мин).
- **Условия GitHub.** Бесплатно — да, но условия Actions (GitHub Terms for Additional Products and Features)
  запрещают на GitHub-hosted runners работу, не связанную со сборкой/тестами/выпуском программы репозитория,
  и как пример — «не использовать Actions как часть serverless-приложения». Ежечасный расчёт данных для
  боевого сайта — серая зона: нагрузка на GitHub мала (качаем с AWS/EUMETSAT, 1–2 мин в час), но GitHub
  вправе отключить Actions. Поэтому: держать репо **не на учётке, с которой деплоится qst-app** (отдельная
  организация/учётка); клиенту оставить запасной путь — старые `/f/` и ИК-формулу; план Б — тот же
  `build_mask.py --upload` раз в час из Планировщика заданий на ПК владельца или на бесплатной VM.
- KV: 2 кадра + манифест в час ≈ 72 записи в сутки (лимит бесплатного тарифа 1000). Хранится до 30 ч
  (TTL): 30 × (0,86 + 3,1) МБ ≈ 120 МБ плюс старые `/f/` ≈ 20 МБ — ~140 МБ из 1 ГБ.
- Воркер (Workers Free): **100 000 запросов в сутки на воркер, общие для `/f/` и `/m/`**, каждый запрос —
  одно чтение KV (лимит тоже 100 000). Полная петля = манифест + 26 кадров ≈ 27 запросов → ~3 700 петель в
  сутки; сверх лимита — ошибка 1027 до 00:00 UTC. Браузер кеширует кадры старше 4 ч на сутки.
- Трафик клиента вырос в 5,6–5,9 раза против `/f/` (2048: 0,86 МБ против 0,15 МБ на кадр). Cloudflare за
  исходящий трафик не берёт; если важен мобильный трафик — `--quality 90`.
- GitHub выключает расписание в публичном репо после 60 дней без коммитов; шаг «Не дать выключить расписание»
  раз в сутки заново включает workflow через API (сбрасывает ли это счётчик, GitHub не обещает — запасной
  вариант: пустой коммит раз в месяц).
